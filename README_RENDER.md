# Deploying Harmony to Render

The blueprint in `render.yaml` creates two things: a Postgres database and the
FastAPI service built from `Dockerfile`. The Next.js frontends are **not** part
of it — deploy those separately (Vercel is easiest) once they talk to the API.

## Before you start

Have these ready — Render will prompt for them:

| Value | Where it comes from |
|-------|--------------------|
| `MISTRAL_API_KEY` | console.mistral.ai |
| `QDRANT_URL` | Qdrant Cloud cluster URL |
| `QDRANT_API_KEY` | Qdrant Cloud → API keys |
| `CORS_ORIGINS` | your frontend's deployed URL (leave blank until it exists) |

`APP_SECRET_KEY` is generated by Render automatically — do not set it by hand.
`APP_DATABASE_URL` is wired from the database automatically.

## Deploy

1. Render dashboard → **New** → **Blueprint**.
2. Connect the GitHub account that owns this repo. Because the repo is
   **private**, you must grant Render access to it specifically — on the GitHub
   authorisation screen choose *Only select repositories* and tick this one.
3. Pick the repo. Render finds `render.yaml` and shows the plan: one database
   (`harmony-db`) plus one web service (`harmony-api`).
4. Fill in the four secrets above when prompted.
5. **Apply**. First build takes roughly 5–10 minutes — the image compiles the
   full LangChain/Qdrant dependency set.

When it goes live, check:

```
https://<your-service>.onrender.com/healthz   -> {"status":"ok","database":"up"}
https://<your-service>.onrender.com/docs      -> Swagger
```

Then create the first account via `POST /api/auth/signup` — the first user of a
new org becomes its `owner`.

## Things that will bite you

**Free Postgres is deleted after 90 days.** Render does not keep it. If this is
more than a demo, move to a paid database plan before you put real data in it.

**The free web service sleeps after ~15 minutes idle**, and a cold start takes
around a minute. A review request already takes ~30s of Mistral calls, so on the
free plan the first request after idle can look like a hang. `plan: starter` in
`render.yaml` avoids this; drop it to `free` only if you accept the sleep.

**Memory.** LangChain, qdrant-client and the Mistral SDK are not small. The free
plan's 512MB is tight and can OOM during a review. Starter (512MB) or Standard
(2GB) is the safer floor — watch the metrics tab after your first few reviews.

**One worker per container, on purpose.** The `CMD` does not pass `--workers`.
Each worker holds its own Qdrant client and embedding model, so scale by raising
the instance count, not the worker count.

**Region.** Keep `harmony-db` and `harmony-api` in the same region (both are set
to `oregon`). A cross-region database adds latency to every request.

## After the API is live

Set `CORS_ORIGINS` to the frontend's real origin, e.g.

```
CORS_ORIGINS=https://harmony-web.vercel.app
```

and set `NEXT_PUBLIC_API_URL` on the frontend to the Render service URL. Both
need to be exact — no trailing slash.
